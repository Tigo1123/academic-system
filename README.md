أهلاً بك في الدليل الشامل لمشروع تخرجك! تم تصميم وبناء هذا النظام بالكامل وفقًا لأعلى المعايير الأكاديمية والبرمجية، ليخدم كنموذج جاهز ومثالي للمناقشة أمام لجان التقييم الجامعية.

## 📂 هيكل ملفات المشروع (Project Structure)

تم تنظيم المشروع باتباع بنية الفصل الكامل بين الواجهة الخلفية (Backend API) والواجهة الأمامية (Frontend Portal) لضمان سهولة الصيانة والتنظيم الاحترافي:

```text
student-results-system/
├── backend/                  # خادم النظام والـ APIs (Node.js & Express)
│   ├── config/
│   │   └── db.js             # الاتصال بقاعدة البيانات والتهيئة التلقائية للمشروع
│   ├── middleware/
│   │   └── auth.js           # برمجية التحقق والتفويض وصلاحيات الأدوار (JWT Middleware)
│   ├── routes/
│   │   ├── admin.js          # مسارات وإجراءات الإدارة (الطلاب، المحاضرين، المواد، التسجيل)
│   │   ├── auth.js           # مسار تسجيل الدخول الموحد لجميع الفئات
│   │   ├── lecturer.js       # مسارات المحاضرين (عرض المواد ورصد الدرجات المباشر)
│   │   └── student.js        # مسارات الطلاب (جلب كشف الدرجات وحساب المعدل GPA)
│   ├── .env                  # ملف إعدادات البيئة السرية وقاعدة البيانات
│   ├── package.json          # حزم وتبعيات خادم الـ Node.js
│   └── server.js             # نقطة الدخول الرئيسية وتوجيه السيرفر
├── frontend/                 # الواجهة الرسومية التفاعلية (HTML, CSS, JS)
│   ├── css/
│   │   └── style.css         # التنسيق والمظهر الجمالي الاحترافي (Glassmorphism & Gradients)
│   ├── js/
│   │   └── app.js            # منطق الاتصال بـ API، تتبع حالة الدخول ونظام التنبيهات (Toast)
│   ├── index.html            # بوابة تسجيل الدخول الموحدة
│   ├── admin.html            # لوحة تحكم الإدارة العامة
│   ├── lecturer.html         # لوحة تحكم المحاضر (رصد وتعديل الدرجات)
│   └── student.html          # لوحة الطالب (بيان كشف الدرجات وعرض المعدل التراكمي GPA)
└── schema.sql                # مرجع هيكل الجداول والبيانات الافتراضية لقاعدة البيانات
```

## 🧠 الجانب النظري ومناقشة التخرج (System Theoretical Aspects)

أثناء مناقشة لجنة التخرج، قد تُسأل عن أسباب اتخاذ بعض القرارات التصميمية والبرمجية. إليك الإجابات العلمية المجهزة لدعمك:

### 1. لماذا اخترنا قاعدة بيانات علائقية (Relational Database) MySQL؟
*   **الإجابة الأكاديمية**: لأن نظام النتائج يعتمد بشكل كلي على **العلاقات المترابطة والصلبة** (الطلاب مسجلون في مواد، والمحاضرون يدرسون مواد، والنتائج تربط الطالب بالمادة). تدعم MySQL خاصية **Integrity Constraints** (مثل المفاتيح الخارجية `FOREIGN KEY` والـ `ON DELETE CASCADE`) مما يمنع حدوث أخطاء فادحة، فمثلاً إذا تم حذف طالب من النظام، يتم تلقائياً حذف تسجيله في المواد ودرجاته لمنع وجود بيانات ميتة أو معلقة (Orphan Rows) في الجداول.

### 2. لماذا اخترنا بروتوكول JWT (JSON Web Tokens) للمصادقة بدلاً من الـ Sessions التقليدية؟
*   **الإجابة الأكاديمية**: بروتوكول JWT هو الخيار الحديث لبناء **RESTful APIs Stateless**. الميزة هنا أن خادم الويب (Server) لا يقوم بحفظ حالة الدخول الخاصة بكل مستخدم في ذاكرته، بل يقوم بتشفير بيانات المستخدم في توكن (Token) يُرسل للواجهة الأمامية ويُحفظ في متصفح المستخدم (`localStorage`). مع كل طلب للـ API، يرسل المتصفح هذا التوكن في الترويسة (`Authorization Header`) ويقوم السيرفر بفك تشفيره فوراً للتأكد من هوية وصلاحية المستخدم، مما يجعل النظام سريعاً وآمناً للغاية وقابلاً للتوسع المستقبلي (Scalable).

### 3. كيف يتم حساب المعدل التراكمي (GPA) في النظام برمجياً؟
*   **الإجابة الأكاديمية**: يتم الحساب بدقة أكاديمية عالية على مقياس **4.0** من خلال احتساب **الساعات المعتمدة (Credits)** وتوزيع النقاط للتقديرات الحرفية كالتالي:
    *   A = 4.0 | B+ = 3.5 | B = 3.0 | C+ = 2.5 | C = 2.0 | D+ = 1.5 | D = 1.0 | F = 0.0
    *   لحل هذه المسألة، نقوم بحساب **نقاط الجودة الإجمالية (Quality Points)** لكل مادة تم رصدها كالتالي: `نقاط الجودة = نقاط تقدير المادة × عدد ساعات المادة`.
    *   المعدل التراكمي (GPA) = `مجموع نقاط الجودة للمواد المرصودة ÷ إجمالي عدد ساعات المواد المرصودة`.
    *   يتم هذا الحساب بالكامل في الخلفية (Backend) لضمان سرية وصحة الحسابات وعدم التلاعب بها من قبل المتصفح.

## 🛠️ دليل تشغيل وتثبيت النظام خطوة بخطوة (How to Run the Project)

لقد قمنا ببرمجة النظام بميزة **"التهيئة الذاتية" (Self-Initialization)**، وهذا يعني أنك لست بحاجة لفتح PHPMyAdmin وإنشاء قاعدة البيانات والجداول ونسخ الأكواد يدوياً! بمجرد تشغيل سيرفر Node.js لأول مرة، سيقوم تلقائياً بإنشاء قاعدة البيانات والجداول وتعبئتها ببيانات تجريبية كاملة.

### المتطلبات المسبقة (Prerequisites)
1. تثبيت برنامج **XAMPP** (أو أي خادم محلي لتشغيل MySQL).
2. تثبيت بيئة **Node.js** على جهازك.

### الخطوات:

#### 1. تشغيل MySQL Server
*   افتح لوحة تحكم **XAMPP Control Panel**.
*   اضغط على زر **Start** بجانب خدمة **MySQL** للتأكد من أنها تعمل في الخلفية.

#### 2. تثبيت المكتبات البرمجية للمشروع (Dependencies)
*   افتح واجهة الأوامر (Terminal / Command Prompt) في مسار مجلد `backend` للمشروع:
    ```bash
    cd backend
    ```
*   قم بتشغيل الأمر التالي لتثبيت كافة الحزم تلقائياً:
    ```bash
    npm install
    ```

#### 3. تشغيل النظام لأول مرة
*   تأكد من تعديل ملف الإعدادات البيئية السرية `backend/.env` إذا كانت قاعدة البيانات في جهازك تحتوي على كلمة مرور (الافتراضي بدون باسوورد للمستخدم root).
*   شغّل السيرفر عبر الأمر:
    ```bash
    npm start
    ```
*   ستشاهد في واجهة الأوامر رسائل نجاح تفاعلية تبين لك إنشاء قاعدة البيانات وتعبئة الجداول بالبيانات التجريبية بنجاح!

#### 4. فتح واستعراض لوحة التحكم
*   افتح متصفح الويب المفضل لديك واذهب إلى الرابط التالي:
    ```text
    http://localhost:5000
    ```
*   ستفتح لك واجهة بوابة الدخول الموحدة فائقة الجمال والتصميم!

## 🚀 نصائح ذهبية عند تقديم العرض النهائي (Presentation Tips)

1. **ابدأ بالمسؤول (Admin)**: سجل الدخول بحساب `admin` واستعرض لوحة التحكم. قم بإضافة مادة جديدة (مثلاً: "Artificial Intelligence" بالرمز "CS-401"). ثم أضف طالباً جديداً، ومحاضراً جديداً.
2. **استعرض الربط (Linking)**: اربط الطالب الجديد بالمادة الجديدة، واربط المحاضر الجديد بذات المادة لتظهر الصلاحيات الأمنية.
3. **انتقل للمحاضر (Lecturer)**: سجل خروجك وادخل بحساب المحاضر الجديد. افتح المادة الجديدة ورشح الطالب الجديد لإدخال درجته (مثلاً: 95). احفظ الدرجة وأظهر كيف تغير التقدير الحرفي تلقائياً إلى (A).
4. **انهي العرض بالطالب (Student)**: سجل دخولك بحساب الطالب الجديد، واعرض كشف الدرجات الجميل وشاهد المعدل التراكمي المحسوب بدقة متناهية فوراً!
